## 1. 修复的 Bug（A1–A5，均有测试/冒烟佐证）

### A1 导入器 id 撞车 → 静默丢卡
- **现象**：同一 SillyTavern 卡包内若有多条同名条目（如两条「郑剑」人物志），
  `ImportedCard.id` 落到内部卡时经 `slugifyName` 拍平成同一 id → 后写覆盖先写、**静默丢卡**。
- **修复**（`src/cards/importer.ts`）：
  - 新增 `dedupeIds()`：同包内 memory/scene/character 卡 id 撞车时追加唯一随机后缀
    （world/item/system 保留原样，不破坏包级引用语义）；
  - 单卡入口与 `splitWorldPack` 出口各调用一次。
- **加固**（`src/db/archive.ts`）：`toInternalCard` scene 分支对「不带 scene_ 前缀」的裸 id
  补 `_uid(4)` 随机后缀（此前 memory 有 uid 兜底、scene 没有，仍可能二次 slugify 撞车）。
- **测试**：`test/importer.test.ts` 新增「同包同名人物志拆出独立角色卡，id 全部唯一」。

### A2 FileCardStore 落盘遗漏 → 重启回滚
- **现象**：`FileCardStore` 覆写了 `putCard/pushChatMessage/editChatMessage/…` 触发持久化，
  但 **`deleteCard` 与 `setChatMessageExcluded` 未覆写** → 删卡/出戏开关在
  `PITAVERN_DATA_DIR` 模式下进程重启后全部回滚（卡复活、出戏标记丢失）。
- **修复**（`src/db/file-store.ts`）：补上两个覆写，成功后 `schedulePersist()`；
  同时把 `updateChat` 的 meta 类型补全为含 persona/settings（已含，仅类型收窄对齐）。
- **测试**：`test/file-store.test.ts` 新增「删除卡/出戏开关也持久化（重启后仍生效）」。

### A3 会话级请求目标校验缺失 → 可误操作其它会话
- **现象**：`chat_edit / chat_set_excluded / chat_delete_message / chat_regenerate /
  chat_swipe / persona_set / settings_set / chat_rename / chat_export` 等处理器对
  「显式 `msg.chatId` 指向**非当前会话**」或「无会话」的情况一律静默 fallback 到
  `session.chatId`——前端状态不同步时可能编辑/删除到**非预期会话**的消息。
- **修复**（`src/web/server.ts`）：这些处理器现在要求目标必须是 `session.chatId`
  （当前会话），否则返回「没有当前会话，请先选择/新建一个会话」；
  保留 `chatBusy` 竞态检查（编辑/删除/出戏在回合处理中仍拒绝）；
  `chat_delete`（显式删除任意会话）与 `chat_export` 语义保持不受影响。
- **验证**：WS 冒烟脚本实测——跨会话 `chat_edit` 收到预期错误，正常
  persona/settings 读写不受影响。

### A4 组装器分层折叠死代码 + 总量兜底缺失
- **现象**（`src/stages/assembler.ts`）：
  - 分层摘要的「超预算折叠」逻辑被 `&& false` 永久关闭——**死代码**，超预算时
    摘要链静默全量贴入，可能推高上下文超 900 token；
  - 常驻卡段对空 detail/description 的 memory/物品仍生成空壳条目；
  - `MAX_PROMPT_TOKENS` 常量定义了却从未使用（无最终总量兜底）。
- **修复**：
  - 分层摘要超预算时按「从最老段整体折叠」保留最近剧情语义并标注归档层数；
  - 常驻卡无正文则跳过（不再贴空壳）；
  - 新增 `truncateHeadToBudget`（`src/utils/tokens.ts`）：总量仍超 900 时**从头部裁**
    （保尾部玩家最新输入不丢），并置 `wholeTruncated`。

### A5 会话层摘要互相串味（世界目录共享）
- **现象**：会话模式压缩出的层摘要卡 id 固定为 `mem_l{from}_{to}` 并写入**世界目录**；
  多个会话压缩同一区间 → 互相覆盖；`loadWorldIndex` 世界级视图也会把它们全部列出
  并贴进其它会话上下文（串剧情）。
- **修复**：
  - `summarizer.ts`：会话模式摘要卡 id 带会话后缀
    `mem_l{from}_{to}_{chatTail}`，幂等删除仅精确匹配自己的 id；
  - `pipeline.ts`：`loadWorldIndex(store, worldId, { chatId })` 新增可选参数——
    无 chat 上下文（世界级/画廊/预览）过滤全部会话摘要卡；带 chatId 只保留本会话的；
  - `server.ts`：`runOneTurn` 与 world_select 预览改用 `{ chatId }` 加载索引。
- **测试**：`test/summarizer.test.ts` 新增「会话摘要卡按 chat 隔离」用例
  （不同会话同区间各自独立、幂等重压不误删、索引按 chatId 过滤、无会话视图为空）。

2. `src/config/pick-model.ts` 与 `src/config/connect.ts` 两个 CLI 各有 `writeEnv`，

6. **无 lint / 无 CI / 无格式化配置**（无 .eslintrc/.prettierrc）；README 自称 27 测试
   但实际已 54 项，README「快速开始」的测试数描述过期；

## 6. 后续建议（按优先级）

1. **产品/测试**：WS 协议自动化测试（`docs/architecture-review.md` 建议 #3 仍未落地）；
2. **工程**：补 eslint/prettier + CI（`npm ci && npm run typecheck && npm test`）；
3. **工程**：README 测试数 27→54、补「审计报告」链接；package.json 增 `dev:web` watch 脚本；
4. **数据**：`PITAVERN_DATA_DIR` 未设时数据仅存内存，退出即失——产品化应默认开启文件目录；
