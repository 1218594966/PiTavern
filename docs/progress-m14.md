# M14 PreRouter 架构升级（叙事导演化）

> 用户架构指正：PreRouter 应该是「剧情摘要 + 近 N 层全文」——与记忆分层设置保持一致，
> 模型知道**全部剧情大概 + 近 N 层细节**才有编排的可能；然后通过工具调用**召回世界库卡片**；
> 而世界库里本就全量存在的卡（世界观/主线大纲/**手工或默认设定的主要NPC**）**不需要召回**。
> 用户确认三决定：常驻角色=设定常注入、在场仍按剧情（B）；路由剧情视图=摘要链+近N层全文
> 与分层同参；常驻角色仍在路由目录但标「主要·常驻·可点名」。

## 落地
### 路由剧情输入（buildRouterContext + pipeline）
- pipeline：路由窗口 `recentHist(min(400, max(8, layerBuffer*6)))`（不再只有 8 行），
  排除刚 push 的本回合行；传 `layerSummaries`（全部层回顾链）
- 路由提示词 user 呈现两段式剧情视图：
  - `【剧情回顾 · 压缩摘要链】`（l1-20、l21-40… 全部剧情压缩回顾）
  - `【近期剧情 · 近几层全文】`（缓冲层内原文，与组装器同口径）

### 人物目录分级（buildRouterContext）
- 目录行标注：`📌主要·常驻`（constant 角色——设定已全量掌握，需要可点名登场）
  vs 未在场可召唤；已在场照标
- WorldIndex.characters 项加 constant 标记（路由池保留常驻角色，可点名）

### 常驻角色语义 B（assembler）
- 修复漏洞：原对 constant 角色 `continue` 跳过 → 现在渲染为 `【主要人物 · 常驻】` 节
  （renderCard 全卡注入，charName 用其自身名）
- 快照去重：路由点名到场的常驻角色不再重复贴快照（其设定已全量在常驻区）
